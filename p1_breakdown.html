Issue #10 · stdout mutation in watch mode ~5 min

limitlens/cli.py700–730

In --watch mode, the CLI captures rendered output by swapping the global sys.stdout to a StringIO, then restores it after rendering. But there is no finally guard, so any exception during rendering leaves sys.stdout permanently bound to the discarded buffer — and every subsequent print() in the process writes into the void.

The bug

700:     if args.watch:
701:         _prev_lines = [0]
702:
703:         def _clear_watch():
704:             n = _prev_lines[0]
705:             if n > 0:
706:                 print(f"\033[{n}A\033[J", end="", flush=True)
707:
708:         try:
709:             while True:
710:                 result = fetch_and_refresh()
711:                 _record(result)
712:                 if not args.json:
713:                     import io as _io
714:                     import sys as _sys
715:                     _clear_watch()
716:                     buf = _io.StringIO()
717:                     _orig = _sys.stdout
718:                     _sys.stdout = buf                 # <-- sys.stdout swapped to buf
719:                     display_result(result)            # <-- can raise
720:                     _sys.stdout = _orig               # <-- only on success
721:                     output = buf.getvalue()
722:                     print(output, end="", flush=True)
723:                     _prev_lines[0] = output.count("\n")
724:                 else:
725:                     display_result(result)
726:                 time.sleep(args.interval)
727:         except KeyboardInterrupt:                     # <-- only KeyboardInterrupt caught
728:             if not args.json:
729:                 print()
730:         return

Failure mode

t=0 sys.stdout = real terminal --> display_result() --> exception raised --> main() except tries to print "[LimitLens] An unexpected error occurred." --> print() writes into the dead StringIO --> process exits, user sees nothing

Fix

_orig = _sys.stdout
_sys.stdout = buf
try:
    display_result(result)
finally:
    _sys.stdout = _orig            # <-- always restored

Even better: refactor display_result to return a string instead of printing. Then watch mode never mutates sys.stdout at all, and the StringIO hack disappears. This also fixes a subtler bug: sys.stdout.isatty() returns False for the StringIO, so color/width detection is wrong during capture.

Issue #8 · Hand-rolled gRPC parser ~2 h

limitlens/providers/grok.py106–130

_parse_grpc_percent() extracts a float from a gRPC-Web + protobuf response by hand-parsing the byte stream. It assumes an undocumented, unversioned wire layout and makes no bounds checks. The try/except Exception: return None at the bottom guarantees it can never crash — but it also means any malformed input looks identical to "no data".

Current implementation with unchecked assumptions

106: def _parse_grpc_percent(data):
107:     """Extract float from gRPC-Web proto (field 1 of outer field 1)."""
108:     try:
109:         idx = 0
110:         while idx + 5 <= len(data):
111:             flag = data[idx]
112:             length = struct.unpack('>I', data[idx+1:idx+5])[0]
113:             body = data[idx+5:idx+5+length]    # [A4] no len(body) == length check
114:             idx += 5 + length                  # [A5] can jump past EOF on bogus length
115:             if flag == 0 and len(body) > 6 and body[0] == 0x0a:
116:                 pos = 1
117:                 val = 0
118:                 shift = 0
119:                 while pos < len(body):        # [A7] no iteration cap
120:                     b = body[pos]
121:                     pos += 1
122:                     val |= (b & 0x7f) << shift  # [A8] val unused, shift unbounded
123:                     if not (b & 0x80):
124:                         break
125:                     shift += 7
126:                 if pos < len(body) and body[pos] == 0x0d:
127:                     return struct.unpack('<f', body[pos+1:pos+5])[0]   # [A10] no pos+5 <= len
128:     except Exception:                          # [A11] swallows every error → return None
129:         pass
130:     return None

Byte layout it assumes (undocumented endpoint)

┌─────────────── gRPC-Web frame ───────────────┐ ┌─── protobuf body ───┐
│ flag(1) │ length(4 BE) │   body(L bytes)      │ │ tag 0x0a │ len(V)  │ 0x0d │ float(4 LE) │
└─────────┴──────────────┴──────────────────────┘ └─────────┴─────────┘ └─────┴────────────┘
   [0]        [1..5]          [5..5+L]                      [0]       [1..V+1]   pos    pos+1..pos+4

The val varint (the submessage's declared length V) is computed but never used. The parser works only because the submessage's first and only field is the float, so the byte right after the length varint happens to be 0x0d. Add a sibling field and the parser silently misfires.

What each missing check costs

TagMissing checkFailure mode
[A4]len(body) == lengthTruncated frame → silent data loss; loop ends
[A5]Bogus length doesn't re-syncAll subsequent valid frames skipped
[A7]Varint iteration cap (max 10)All-high-bit bytes spin until EOF
[A8]Cap val against submessage sizeCrafted body can place "float" anywhere
[A10]pos+5 <= len(body) before unpackTruncated tail → struct.error → caught → None

Proposed fix shape

def _parse_grpc_percent(data):
    try:
        if not isinstance(data, (bytes, bytearray)) or len(data) < 6:
            return None
        idx = 0
        while idx + 5 <= len(data):
            flag   = data[idx]
            length = struct.unpack('>I', data[idx+1:idx+5])[0]
            if idx + 5 + length > len(data) or length > 1 << 20:   # cap frame size
                return None
            body = data[idx+5:idx+5+length]
            idx += 5 + length
            if flag == 0 and body[:1] == b'\x0a':
                pos, val, shift = 1, 0, 0
                for _ in range(10):                                  # varint cap
                    if pos >= len(body): break
                    b = body[pos]; pos += 1
                    val |= (b & 0x7f) << shift
                    if not (b & 0x80): break
                    shift += 7
                if pos + 5 <= len(body) and body[pos] == 0x0d:
                    return struct.unpack('<f', body[pos+1:pos+5])[0]
    except (struct.error, IndexError) as e:
        log.debug("grok parser: malformed frame: %s", e)
        return None
    return None

Add fixtures: truncated frame, oversized length, malformed varint, submessage with sibling field, trailer frame. Currently zero parser tests exist.

Issue #6 · Drifted provider defaults with #5

limitlens/config.py8–97  |  limitlens/cli.py73–86, 355–379

DEFAULT_CONFIG declares one set of "enabled by default" booleans. The CLI's enabled_count and doctor rows declare different booleans. They have already drifted, and there is no single source of truth.

Drift table

ProviderDEFAULT_CONFIGCLI enabled_countDoctor listStatus
piTrueFalseFalseconfig says on, CLI treats as off
kiloTrueFalsemissingconfig says on, CLI never counts it; missing from doctor
copilot_cliTruenot countedmissingenabled by config, invisible to CLI

Why it bites users

  • A user who runs limitlens --init-config gets pi: enabled: true and kilo: enabled: true in their config, but limitlens status never fetches them unless they pass --tool pi or --tool kilo explicitly. The enabled_count block is the gate, and it gates them out.
  • limitlens doctor tells the user "Grok: not configured" (correct) and "Cline: configured" (correct), but never even lists Kilo — so the user can't tell from doctor whether Kilo is reachable.
  • Two pi defaults disagree across files, so the same config behaves differently depending on which code path reads it.

Falls out of #5 — once each provider descriptor owns its default_enabled bool, every other site (config defaults, CLI gating, doctor rows, menubar row collection) reads from the descriptor and the drift vanishes.

Proposed descriptor shape

# limitlens/providers/__init__.py
@dataclass(frozen=True)
class ProviderDescriptor:
    key: str                       # canonical key, matches config["key"]
    label: str                     # display label, e.g. "Codex"
    aliases: tuple[str, ...]       # CLI aliases, e.g. ("agy", "antigravity")
    config_key: str                # config dict key (default = key); "custom" → "custom_tools"
    default_enabled: bool
    fetch: Callable                # get_*_data
    display: Callable | None       # display_*_text, or None
    display_section: str           # "Quota" or "Observed" — for grouping
    auto_detect: Callable | None   # for config.auto_detect_providers
    unit_hint: str = "%"           # "$", "%", etc. for menubar

PROVIDERS: dict[str, ProviderDescriptor] = { ... }   # 13 entries, one per provider

What becomes data-driven

  • Imports — descriptor holds the function reference, no top-level import list needed
  • --tool choices — derived from PROVIDERS.keys() ∪ aliases
  • Doctor rows — derived from (p.label, p.default_enabled)
  • Labels — derived from p.label; --tool kilo can no longer KeyError
  • enabled_count — sum(1 for p in PROVIDERS.values() if is_active(p))
  • Fetch dispatch — {p.key: ex.submit(p.fetch, args, config) for p in active}
  • Display dispatch — p.display(result[p.key], args) if p.display else None
  • Menubar _collect_rows — iterates descriptors, can no longer "forget" a provider

What this is NOT

It is not a plugin system. A descriptor is one frozen dataclass per provider, declared in the existing limitlens/providers/__init__.py file. Discovery, registration, and packaging are unchanged. The point is to centralize metadata, not to add indirection.

Proposed fix (grok.py)

def fetch_grok_usage(sso_cookie):
    try:
        req = urllib.request.Request(...)
        req.add_header('cookie', f'sso={sso_cookie}; sso-rw={sso_cookie}')
        with urllib.request.urlopen(req, timeout=10) as resp:
            if resp.status != 200:
                log.warning("grok: HTTP %s from billing endpoint", resp.status)
                return {"error": f"http_{resp.status}"}
            return _parse_grpc_percent(resp.read())
    except urllib.error.HTTPError as e:
        if e.code == 403:
            return {"error": "auth_expired", "detail": "SSO cookie may have expired; re-auth with grok CLI"}
        return {"error": f"http_{e.code}"}
    except urllib.error.URLError as e:
        return {"error": "network", "detail": str(e.reason)}
    except (socket.gaierror, TimeoutError) as e:
        return {"error": "dns_or_timeout", "detail": str(e)}

Repo-wide pattern: replace each except Exception with the narrowest set of types the call site can actually raise, and at minimum log.exception(...) on the unexpected remainder. The 18 in menubar.py are most painful because they're in a UI loop — the user has no idea their refresh has been silently failing.

The user-visible path (_set_refresh_failure, line 1126) runs redact_text() and a regex scrubber for tokens/cookies/paths. The log-write path on line 1398 does none of that. proc.stderr can include:

  • Stack traces with file paths (/Users/<name>/...)
  • Provider exception messages that quote cookies or Authorization headers
  • Config error messages that include the user config path

This is a P0-adjacent privacy bug: anything a provider prints to stderr ends up in ~/.cache/limitlens/limitlens.log in cleartext, while the same string is redacted before it ever reaches the user. A user who shares their log for support is sharing all of that unredacted.

Proposed logging shape

# limitlens/logging.py
import logging
import os
from logging.handlers import RotatingFileHandler
from .core import redact_text

_LOGGER = None

class RedactFilter(logging.Filter):
    def filter(self, record):
        if isinstance(record.msg, str):
            record.msg = redact_text(record.msg)
        if record.args:
            record.args = tuple(redact_text(a) if isinstance(a, str) else a for a in record.args)
        if record.exc_info:
            record.exc_text = redact_text(record.format_exc()) if hasattr(record, "format_exc") else None
        return True

def get_logger():
    global _LOGGER
    if _LOGGER:
        return _LOGGER
    _LOGGER = logging.getLogger("limitlens")
    _LOGGER.setLevel(os.environ.get("LIMITLENS_LOG_LEVEL", "INFO"))
    log_path = os.environ.get("LIMITLENS_LOG_PATH") or os.path.expanduser("~/.cache/limitlens/limitlens.log")
    handler = RotatingFileHandler(log_path, maxBytes=1_000_000, backupCount=3, encoding="utf-8")
    handler.addFilter(RedactFilter())
    handler.setFormatter(logging.Formatter("[%(asctime)s] %(levelname)s %(name)s: %(message)s"))
    _LOGGER.addHandler(handler)
    return _LOGGER

Migration order

  1. Add limitlens/logging.py with the redaction filter — no callers yet.
  2. Replace the 5 hand-rolled logger copies with log.exception(...) / log.warning(...) — including the unredacted proc.stderr on line 1398.
  3. Convert the 83 print() calls to log.info() (or keep print() for user-facing output and use log.debug() for diagnostics — split them deliberately).
  4. Add a --debug flag that bumps the level to DEBUG and adds a console handler.
